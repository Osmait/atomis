# Architecture

Atomis is a loopback-only local web application. The browser and native runner never share a transport.

```text
React + Monaco
  ├─ /ws/lsp     JSON objects ─ Fastify upgrade ─ LspProxy ─ framed stdio ─ ZLS
  └─ /ws/runtime validated events ─ RunScheduler
                                    ├─ DocumentStore (atomic multi-file src/)
                                    ├─ runzig-instrument (every .zig module)
                                    ├─ zig build instrumented tests
                                    ├─ ProcessSupervisor ─ stdout / stderr / fd 3
                                    └─ atomis-tests ─ custom runner ─ fd 3 NDJSON
```

## Components

- `SessionManager` creates unguessable workspaces under the OS temporary directory and derives every path internally.
- `DocumentStore` owns the monotonic project snapshot and atomically creates, updates, renames and removes validated paths below `src/`.
- `LspProxy` implements byte-correct LSP framing and owns one restart attempt independently of run state.
- Monaco's stable provider APIs are the LSP client layer. This is the current lightweight alternative to `monaco-languageclient`; providers are registered only for ZLS-advertised capabilities.
- `RunScheduler` is the explicit state machine boundary. A new version clears debounce and aborts the previous pipeline.
- `CompilerRunner` mirrors assets, instruments every Zig module, compiles from generated `main.zig`, executes with `src/` as cwd, maps diagnostics and enriches probe/log events with their source path.
- `TestDiscovery` finds `test` blocks in the visible sources and maps runner-qualified names back to files; `CompilerRunner` generates `test_root.zig`, builds `atomis-tests` with the custom `runzig_test_runner.zig` (mode `simple`), executes it after the program run and streams per-test results from fd 3 through `TestEventReader`.
- `ProcessSupervisor` starts detached process groups, enforces time/output limits, sends TERM then KILL, and closes stdin. With the sandbox on it also confines every child (`sandbox.rs`): the Landlock ruleset is built in the parent and the child only issues `prctl(PR_SET_NO_NEW_PRIVS)` + `landlock_restrict_self` between fork and exec — allocating there could deadlock a multi-threaded server. The policy grants read+execute on toolchains and system paths, read+write on that session's workspace, read+write on the handful of character devices builds need (`/dev/null` and friends; `/dev` itself is never granted, so raw disks stay unreachable) and, on Landlock ABI 4+, no TCP (Landlock does not cover UDP). Toolchain caches are redirected into the workspace (`HOME`, `XDG_CACHE_HOME`, `TMPDIR`, `ZIG_*_CACHE_DIR`, `CARGO_HOME`, `GOPATH`, `PYTHONPYCACHEPREFIX`) so a sandboxed session never needs to write outside it; `RUSTUP_HOME` keeps pointing at the real home because it is read-only anyway.

### Workspaces

`POST /api/sessions` without a `workspace` creates an ephemeral session under the OS temp dir, reaped on disconnect and after 24 h — the original model. With one, the session attaches to a **persistent workspace** (`workspace.rs`): a directory under `$XDG_DATA_HOME/atomis/workspaces/<id>` (override with `ATOMIS_WORKSPACES`) holding a self-describing `atomis.json` beside the usual `src/`, `generated/` and caches, so there is no central index to corrupt. `GET/POST /api/workspaces` and `PATCH/DELETE /api/workspaces/{id}` manage them; ids are generated hex and validated before they ever touch a path. Attaching re-scaffolds the language templates (build files, never `src/`) and reads the visible sources back from disk, so files survive reloads, restarts and reboots. The web app remembers the active workspace in `localStorage` and falls back to a scratch session if it has disappeared. Switching is an in-place swap, never a page reload: the runtime WebSocket lives in a session-scoped effect (not in the editor's `onMount`), so opening another session closes the old socket, disposes the LSP clients and the previous workspace's Monaco models — they are keyed by absolute session paths — resets the run state and rebuilds around the new session while the shell dims for 140 ms. The sandbox needs no special case: its policy is derived from the session root, and Landlock resolves by closest rule, so a workspace under the read-only `~/.local` tree stays writable (there is a test for exactly that).

### Frontend structure (`apps/web/src`)

`App.tsx` is an orchestrator: it owns the session bootstrap, the Monaco mount and the runtime WebSocket, and composes everything else.

- `state/` holds the pure, unit-tested logic: `fileTree` (tree rows), `tabs` (cycling/closing), `keyboardNav` (the leader-key decision core — `resolveNavAction`), `diagnostics` (flatten/dedupe/severity), `runSummary` (labels, tones, run history, the drawer auto-open rule), `terminalFolds`, `runtimeState` (inline-value versioning), `paths` (path validation + ws URLs), `settings`/`appearance`/`storage` (validated localStorage persistence).
- `hooks/` binds that logic to React: `useRuntimeEvents` (all state fed by the runtime socket), `useProjectFiles` (files/tabs/tree CRUD), `useKeyboardNav` (zones + leader side effects), `useEditorDecorations` (inline values, error lens, test lens), `usePeekPanel` (view zone + overlay), `useGlobalShortcuts`, `useDismissable`, `useMediaLayout`.
- `components/` are presentational with typed props and jsdom tests: `FileTree`, `EditorChrome`, `Terminal`, `TestsDrawer`, `StatusBar`/`ZenPill`, `ContextMenus`, plus the pre-existing `PeekPanel`, `SettingsModal`, `CommandPalette`, `FileIcon`, `Lucide`.
- `lsp/` speaks LSP: `protocol.ts` (pure wire helpers over a `JsonValue` type — `any`/`unknown` are banned by the linter) and `LspClient.ts` (socket, providers, Monaco markers).

Linting is strict on both sides: `pnpm lint` runs oxlint (pedantic categories as errors; `typescript/no-explicit-any` plus a `no-restricted-types` ban on `unknown`) and `cargo clippy --all-targets -- -D warnings`.

## Multilingual workspaces

`POST /api/sessions` accepts a `language` (zig, rust or go) which only selects the initial entry file. Language support is declared in `apps/server-rs/src/packs.rs` (mirrored by `apps/web/src/languages.ts`): each pack contributes extensions, an entry file, a scaffold, a runner, an instrumenter path and toolchain checks. Every workspace carries the scaffold of every language whose toolchain is present; entry files are protected. Go sessions compile `go build ./generated` into a single `package main`, run tests with `go test -json ./src` (structured per-test events), and instrument with `golive-instrument` (stdlib `go/parser`, byte-exact offsets). TS/JS sessions run `node generated/main.ts` directly (type stripping) with the probe runtime injected via `node --import` — no user file is modified for the runtime — plus a non-blocking `tsc --noEmit` diagnostics pass (native TS 7) and `node --test` TAP for `*.test.ts|js`; the instrumenter `tslive-instrument` uses the `typescript-ast` (TS 5) compiler API. Python sessions run `python3 -u generated/main.py` with the probe builtins installed by a `sitecustomize.py` on PYTHONPATH (the Python mirror of `node --import`), instrument with the stdlib `ast` module (byte-exact line splices), and run `test_*` functions through a custom stdlib runner that emits the same fd 3 NDJSON schema as the Zig runner. C and C++ share one runner: the probe runtime header is injected with `-include` (never touching user files), `clive-instrument` parses clang's JSON AST dump against EMPTY stub headers (recovery keeps VarDecl names/offsets, so the dump stays tiny), previews dispatch via `_Generic` function designators in C and an `operator<<` requires-check in C++, and tests link a generated test main against user objects compiled with `-Dmain=__atomis_user_main`. `RunScheduler` holds one runner per language and dispatches by the edited/active file's extension (`run.request` carries an optional `language`; auto-run derives it from the updated path). `/ws/lsp?lang=zig|rust` multiplexes one `LspProxy` per language so ZLS and rust-analyzer serve the same workspace side by side, and `resetGenerated` preserves both language runtimes when either pipeline rebuilds the mirror. The Rust half of the workspace is a two-target cargo package: `atomis-check` compiles the visible `src/main.rs` (what rust-analyzer and the test build see) and `atomis-session` compiles the instrumented `generated/` mirror. `RustCompilerRunner` drives the same `RunnerCallbacks` contract: `rustlive-instrument` (a vendored-`syn` binary mirroring the `runzig-instrument` CLI/JSON) splices `atomis_probe!`/`atomis_log!` calls, `cargo build --message-format=json --offline` produces structured diagnostics (`CargoDiagnostics`), the binary runs supervised with fd 3 probes, and `cargo test --no-run` plus a supervised libtest run (`--test-threads=1`, parsed by `RustTestOutput`) feeds the shared test events. `RuntimeOutputParser` strips the `\x1eATOMIS_LOG` markers per stream for both languages (Rust `println!` marks stdout, `eprintln!`/`dbg!` mark stderr). `LspProxy` spawns `rust-analyzer` instead of ZLS.

The server defaults to `127.0.0.1:4317`; Vite at `127.0.0.1:5173` proxies both same-origin transports in development.
